    Bases de Datos A

    Fundamentos de las bases de datos: por qué existen, cómo se diseñan con el modelo entidad-relación, cómo se traducen al modelo relacional y los primeros pasos con Oracle y SQL.

    1. Introducción a las bases de datos

    Antes de los SGBD, la información se guardaba en ficheros sueltos gestionados por cada aplicación, con datos duplicados e inconsistentes entre sí. Un SGBD (Sistema Gestor de Bases de Datos) centraliza el almacenamiento y ofrece control de acceso, integridad y consultas eficientes sobre esos datos.

    • Ventajas: menos redundancia, datos consistentes, acceso concurrente y seguro. Inconvenientes: mayor complejidad y coste de implantación.
    • ANSI/X3/SPARC: arquitectura estándar en tres niveles (externo, conceptual, interno) que separa cómo ve los datos cada usuario, cómo se modelan lógicamente y cómo se almacenan físicamente.
    • Modelos y tipos de BBDD: jerárquico, en red, relacional (el más extendido) y orientado a objetos; y por despliegue, centralizadas (un único servidor) frente a distribuidas (los datos repartidos entre varios nodos).
    • Big data: volúmenes de datos tan grandes o variados que superan la capacidad de los SGBD relacionales tradicionales.
    • Legislación: normativa de protección de datos (como el RGPD) que regula cómo se pueden almacenar y tratar los datos personales.
    ¿Sabías que...?

    El modelo relacional lo inventó Edgar F. Codd en 1970 mientras trabajaba en IBM. Su idea de organizar los datos en tablas con claves, en vez de estructuras jerárquicas rígidas, sigue siendo la base de la mayoría de bases de datos actuales.

    2. Modelo entidad-relación

    Es la herramienta de diseño conceptual (independiente de cualquier SGBD concreto) con la que se representa la información del mundo real antes de construir la base de datos. Se apoya en tres elementos: entidades (objetos del mundo real, representadas como rectángulos), atributos (propiedades de una entidad, como óvalos) y relaciones (vínculos entre entidades, como rombos) — la misma notación que resume el Anexo de representación gráfica.

    • El modelo E-R extendido añade jerarquías de generalización/especialización (entidades "padre" e "hijas").
    • La guía para construir un modelo E-R propone un método ordenado: identificar entidades, sus atributos, las relaciones entre ellas y por último las cardinalidades.

    3. Modelo relacional

    Traduce el diseño conceptual (entidades y relaciones) a un diseño lógico: tablas (relaciones), filas (tuplas) y columnas (atributos), cada una con un dominio de valores válidos.

    • Tipos de clave: candidata (cualquier atributo que podría identificar una fila de forma única), primaria (la candidata elegida), ajena o foránea (referencia a la clave primaria de otra tabla) y alternativa (las candidatas no elegidas como primaria).
    • Valores nulos: representan la ausencia de un dato, no un cero ni una cadena vacía.
    • Reglas de integridad: la de entidad exige que la clave primaria nunca sea nula; la referencial exige que una clave ajena siempre apunte a un valor existente (o sea nula).
    • Traducción E-R → relacional: cada entidad se convierte en una tabla, y las relaciones se resuelven con claves ajenas (o con una tabla intermedia en relaciones muchos-a-muchos).

    4. Normalización

    Proceso que reorganiza las tablas para eliminar redundancias e inconsistencias, basándose en las dependencias funcionales entre atributos (cuando el valor de uno determina el de otro). Se avanza por formas normales sucesivas: la 1FN exige que cada campo contenga un único valor atómico (nada de listas o valores repetidos dentro de una misma celda).

    Cada forma normal exige lo anterior, y añade una condición más estricta.

    5. Primeros pasos en SGBD Oracle

    Puesta en marcha práctica de Oracle como SGBD real, antes de empezar a escribir SQL.

    • Oracle Database: el motor en sí, donde vive físicamente la información (puede instalarse localmente o usarse una instancia en la nube).
    • Oracle SQL Developer: la herramienta gráfica más habitual para conectarse al SGBD, explorar tablas y ejecutar consultas sin usar la línea de comandos.
    • Usuario y esquema: en Oracle, cada usuario tiene asociado su propio esquema (su conjunto de tablas), a diferencia de otros SGBD donde el esquema es independiente del usuario.
    • Primera conexión: se necesita el host, el puerto, el nombre del servicio (o SID) y las credenciales del usuario para establecer la conexión desde SQL Developer.

    6. Lenguajes de las BBDD. SQL

    SQL (Structured Query Language) es el lenguaje estándar para trabajar con bases de datos relacionales, dividido en varios subgrupos: DDL (Data Definition Language, para crear y modificar tablas con CREATE/ALTER/DROP), DML (Data Manipulation Language, para consultar y modificar datos con SELECT/INSERT/UPDATE/DELETE) y DCL (Data Control Language, para permisos con GRANT/REVOKE).

    DMLConsultar y modificar los datosSELECT, INSERT, UPDATE, DELETE
    DCLGestionar permisos de accesoGRANT, REVOKE

    BBDD centralizadas vs. distribuidas

    Una BBDD centralizada guarda todo en un único servidor, al que los usuarios acceden por red (LAN o WAN). Una BBDD distribuida reparte los datos entre varios servidores (incluso en distintos países), pero funciona como si fuera una sola. Por ejemplo, un banco multinacional permite consultar las cuentas desde cualquier país sin depender de un único servidor.

    CentralizadaDistribuida
    Si cae el servidorCae todo el sistema (punto único de fallo)Otros nodos asumen sus funciones
    EscalabilidadLimitadaAlta: se añaden nodos
    RendimientoCuello de botella con muchos usuariosCarga repartida y datos más cerca del usuario
    Complejidad y costeMenor: control y mantenimiento en un solo puntoMayor: hay que sincronizar los nodos

    El SGBD: funciones y tipos

    Un SGBD es el software que permite diseñar, consultar y modificar una base de datos de forma eficiente y segura. Sus funciones son:

    • Definir datos (DDL) y manipularlos (DML).
    • Optimizar consultas con índices y caché.
    • Gestionar la concurrencia de varios usuarios a la vez.
    • Seguridad: autenticación y permisos.
    • Integridad: claves y restricciones.
    • Transacciones con propiedades ACID.
    ClasificaciónTipoEjemplos
    Por capacidadOfimáticos: bases pequeñas, uso personalMicrosoft Access, SQLite
    Empresariales: grandes volúmenes y muchos usuariosOracle, IBM Db2, SQL Server
    Por licenciaComerciales (de pago)Oracle, SQL Server, IBM Db2
    Código abiertoMySQL, PostgreSQL, MariaDB

    Los tres niveles ANSI/SPARC

    • Externo (o de visión): lo que ve cada usuario. Por ejemplo, RR.HH. solo ve los datos de empleados y Finanzas solo las nóminas.
    • Conceptual (o lógico): la estructura global, con qué tablas hay (Clientes, Pedidos...), cómo se relacionan y qué restricciones tienen, sin entrar en cómo se guardan.
    • Interno (o físico): cómo se almacenan realmente los datos en disco (archivos, índices, organización secuencial o indexada).

    Separar niveles da independencia de los datos: se puede cambiar el almacenamiento físico sin tocar el esquema lógico, y el esquema lógico sin afectar a las vistas de los usuarios.

    Big Data y Power BI

    Big Data son conjuntos de datos tan grandes y complejos que no se pueden procesar con técnicas tradicionales. Se define con las 3V:

    • Volumen: de terabytes a petabytes.
    • Velocidad: datos generados en tiempo real, como los sensores IoT.
    • Variedad: datos estructurados, semiestructurados y no estructurados (tweets, imágenes, vídeos, emails...).

    A veces se añaden dos V más: Veracidad (calidad de los datos) y Valor (utilidad para decidir).

    Power BI es la herramienta de Business Intelligence de Microsoft. Conecta varias fuentes de datos, los prepara (ETL: extraer, transformar, cargar) y crea dashboards e informes interactivos para tomar decisiones.

    Modelo E-R: lo que más se pregunta

    • Entidad débil: no tiene clave primaria propia y depende de una entidad fuerte (se dibuja con doble rectángulo). Ejemplo: Línea de pedido no existe sin su Pedido, y se identifica con IDPedido + número de línea.
    • Tipos de atributo:
      • Simple: Nombre.
      • Compuesto: Dirección = calle + número + ciudad.
      • Multivaluado: Teléfonos.
      • Derivado, que se calcula a partir de otros: Edad a partir de la fecha de nacimiento.
      • Clave primaria: se dibuja subrayada.
    • Tipos de relación:
      • 1:1: persona – pasaporte.
      • 1:N: cliente – pedidos.
      • N:M: estudiante – asignaturas.
    • Relación reflexiva (unaria o de anillo): una entidad se relaciona consigo misma con roles distintos. El caso clásico es Empleado–Jefe.
    CREATE TABLE Empleado (
  IDEmpleado INT PRIMARY KEY,
  Nombre     VARCHAR(50),
  IDJefe     INT,
  FOREIGN KEY (IDJefe) REFERENCES Empleado(IDEmpleado)
);

    Cardinalidad (mín., máx.): 0..1 es cero o uno, 1..1 exactamente uno, 0..N cero o muchos y 1..N al menos uno.

    ¿Cuántas tablas crea una relación 1:N?

    Dos: una por cada entidad. El lado N recibe la clave primaria del lado 1 como clave ajena. Por ejemplo, Pedido incluye IDCliente.

    Grado y cardinalidad de una tabla

    El grado es el número de columnas (atributos). La cardinalidad es el número de filas. Una tabla municipios(id, nombre, poblacion) tiene grado 3, tenga las filas que tenga.

    Normalización y 1FN

    Normalizar sirve para eliminar redundancias y evitar anomalías al insertar, actualizar o borrar. Un ejemplo típico que no cumple 1FN es tener 666777888, 666888999 en una sola celda "Teléfonos". Se corrige dejando un único valor atómico por celda.

    Forma normalRequisito
    1FNValores atómicos, sin grupos repetitivos
    2FN1FN + dependencia funcional completa de la clave
    3FN2FN + sin dependencias transitivas
    FNBCBoyce-Codd: más restrictiva que la 3FN

    SQL: la pregunta trampa y las consultas típicas

    ¿SELECT es DDL o DML? Es DML, porque consulta datos y no define estructura. Además de DDL, DML y DCL existe TCL (control de transacciones): COMMIT, ROLLBACK, SAVEPOINT. Y ojo a esta diferencia: DROP TABLE borra la tabla entera, mientras que TRUNCATE TABLE vacía todas las filas pero conserva la estructura.

    -- Filtrar con WHERE
SELECT nombre, poblacion
FROM municipios
WHERE poblacion > 6000;

-- INNER JOIN: solo filas con coincidencia en ambas tablas
SELECT c.nombre, p.fecha
FROM Clientes c
INNER JOIN Pedidos p ON c.id_cliente = p.id_cliente;

    Operadores habituales en WHERE:

    • =, <> (o !=), >, <.
    • BETWEEN 1000 AND 5000: entre dos valores.
    • LIKE 'Ma%': coincidencia de patrón.
    • IN (1, 2, 3): pertenencia a una lista.

    El INNER JOIN del ejemplo deja fuera a los clientes que no tienen pedidos.

    Restricciones y acciones referenciales

    Además de la clave primaria, una tabla puede llevar restricciones que protegen la calidad de los datos: NOT NULL (la columna no admite nulos), UNIQUE (sin valores repetidos), CHECK (una condición que cada fila debe cumplir) y FOREIGN KEY. En las claves foráneas se puede indicar qué ocurre al borrar la fila referenciada con ON DELETE: RESTRICT/NO ACTION impiden el borrado, CASCADE borra también las filas que la referencian y SET NULL pone la clave foránea a nulo. PostgreSQL añade SET DEFAULT; la misma idea existe para ON UPDATE.

    Vistas

    Una vista es una consulta con nombre que se comporta como una tabla virtual. No duplica los datos: cada vez que se consulta, se ejecuta la consulta que la define. Sirven para reutilizar consultas complejas y para abstraer la estructura de las tablas, mostrando solo las columnas que interesan.

    CREATE VIEW clientes_activos AS
  SELECT id_cliente, nombre FROM clientes WHERE activo = 1;

    El orden lógico de una consulta SELECT

    Aunque se escribe empezando por SELECT, una consulta se evalúa lógicamente en otro orden: primero FROM (y los JOIN), luego WHERE, GROUP BY y HAVING, después se calcula la lista del SELECT, luego DISTINCT, y al final ORDER BY y LIMIT. Esto explica por qué WHERE filtra filas antes de agrupar y HAVING después, y por qué un alias definido en el SELECT no se puede usar en el WHERE. Es el orden conceptual: el optimizador puede ejecutar la consulta de otra forma siempre que el resultado sea el mismo.

    Fuentes: PostgreSQL: restricciones · PostgreSQL: vistas · PostgreSQL: SELECT Los conceptos son del estándar SQL; la documentación enlazada es la de PostgreSQL.

    Puntos clave

    • Un SGBD centraliza el almacenamiento y evita la redundancia e inconsistencia de los ficheros sueltos.
    • El modelo E-R (entidades, atributos, relaciones) es el diseño conceptual, previo a las tablas.
    • La clave primaria identifica de forma única cada fila; la clave ajena referencia la clave primaria de otra tabla.
    • La normalización elimina redundancias aplicando formas normales sucesivas (1FN, 2FN, 3FN...).
    • SQL se divide en DDL (definir), DML (manipular) y DCL (permisos).

    Ponte a prueba

    ¿Qué diferencia hay entre una clave primaria y una clave ajena?

    La primaria identifica de forma única cada fila de su propia tabla; la ajena referencia la clave primaria de otra tabla para relacionar ambas.

    ¿Qué exige la primera forma normal (1FN)?

    Que cada campo contenga un único valor atómico, sin listas ni valores repetidos dentro de una misma celda.

    ¿Qué tipo de sentencias SQL pertenecen al DDL?

    Las que definen la estructura: CREATE, ALTER, DROP.

    ¿Qué es un valor nulo en una base de datos?

    La ausencia de un dato; no es lo mismo que cero o una cadena vacía.

    ¿Qué garantiza la regla de integridad de entidad?

    Que la clave primaria de una tabla nunca puede ser nula.
