    8. Control de transacciones y concurrencia

    Una transacción es un conjunto de operaciones que se ejecutan como una unidad indivisible: o se completan todas, o no se aplica ninguna.

    • Propiedades ACID: Atomicidad, Consistencia, Aislamiento y Durabilidad garantizan que la transacción sea fiable incluso ante fallos.
    • Estados de una transacción: activa, parcialmente confirmada, confirmada (COMMIT) o abortada (ROLLBACK).
    • Ejecución concurrente: cuando varias transacciones acceden a los mismos datos a la vez pueden aparecer problemas como lecturas sucias o pérdidas de actualización; el control de concurrencia (bloqueos, niveles de aislamiento) evita estos conflictos.
    • Recuperación ante errores: mecanismos para devolver la base de datos a un estado consistente tras un fallo (por ejemplo, deshaciendo transacciones incompletas).
    ¿Sabías que...?

    El acrónimo ACID (Atomicidad, Consistencia, Aislamiento, Durabilidad) lo popularizó Andreas Reuter en 1983, y sigue siendo el estándar con el que se mide la fiabilidad de cualquier motor de bases de datos transaccional.

    9. Programación en BBDD

    PL/SQL añade a SQL estructuras de control propias de un lenguaje de programación (variables, condicionales, bucles), permitiendo programar lógica directamente dentro de la base de datos.

    • Procedimientos y funciones: bloques de código PL/SQL reutilizables y almacenados en la propia base de datos; una función siempre devuelve un valor, un procedimiento no necesariamente.
    • Cursores: permiten recorrer fila a fila el resultado de una consulta dentro de un bloque PL/SQL.
    • Disparadores (triggers): bloques de código que se ejecutan automáticamente ante un evento (INSERT, UPDATE, DELETE) sobre una tabla, útiles por ejemplo para auditoría o validaciones automáticas.
    -- Procedimiento PL/SQL sencillo
CREATE OR REPLACE PROCEDURE subir_precio(p_id NUMBER, p_pct NUMBER) IS
BEGIN
  UPDATE productos SET precio = precio * (1 + p_pct / 100)
  WHERE id_producto = p_id;
  COMMIT;
END;

-- Trigger que registra cada cambio de precio
CREATE OR REPLACE TRIGGER trg_auditoria_precio
AFTER UPDATE OF precio ON productos
FOR EACH ROW
BEGIN
  INSERT INTO auditoria (id_producto, precio_anterior, precio_nuevo)
  VALUES (:OLD.id_producto, :OLD.precio, :NEW.precio);
END;

    10. Bases de datos no relacionales

    Las bases de datos NoSQL abandonan el modelo de tablas fijas para adaptarse mejor a datos muy variables o a gran escala: documentales (MongoDB), clave-valor, orientadas a columnas o a grafos. MongoDB almacena la información como documentos tipo JSON dentro de colecciones, sin un esquema rígido de columnas como en SQL.

    Tipos de JOIN

    Un JOIN combina filas de dos tablas según una condición. El INNER JOIN solo devuelve las filas que tienen pareja en ambas tablas. El LEFT JOIN devuelve todas las filas de la tabla de la izquierda y, cuando no hay pareja en la derecha, rellena sus columnas con NULL; el RIGHT JOIN hace lo mismo conservando la tabla de la derecha. El FULL JOIN conserva las filas de ambos lados, pero MySQL no lo soporta de forma nativa y suele simularse uniendo un LEFT JOIN y un RIGHT JOIN con UNION. Un truco muy útil del LEFT JOIN es filtrar con IS NULL para encontrar filas sin correspondencia:

    -- Clientes que no han hecho ningún pedido
SELECT c.nombre
FROM clientes c
LEFT JOIN pedidos p ON p.id_cliente = c.id_cliente
WHERE p.id_pedido IS NULL;

    Niveles de aislamiento y anomalías de concurrencia

    Los niveles de aislamiento del estándar SQL definen qué anomalías se toleran cuando varias transacciones se ejecutan a la vez. Las tres clásicas son la lectura sucia (leer datos que otra transacción ha escrito pero aún no ha confirmado), la lectura no repetible (releer una fila y encontrar que otra transacción ya confirmada la ha modificado) y la lectura fantasma (repetir una consulta y obtener un conjunto de filas distinto porque otra transacción confirmada ha añadido o quitado filas). De menos a más aislamiento: READ UNCOMMITTED permite las tres; READ COMMITTED evita las lecturas sucias; REPEATABLE READ evita además las no repetibles; y SERIALIZABLE las evita todas, garantizando un resultado equivalente a haber ejecutado las transacciones una detrás de otra.

    Más aislamiento significa más garantías, pero también más contención entre transacciones, y cada motor implementa los niveles a su manera: por ejemplo, PostgreSQL usa READ COMMITTED por defecto y no permite lecturas sucias ni siquiera en READ UNCOMMITTED.

    Índices: leer más rápido, escribir más despacio

    Un índice es una estructura auxiliar (normalmente un árbol de búsqueda) que permite localizar filas sin recorrer toda la tabla, igual que el índice alfabético de un libro. Acelera las consultas con WHERE y los JOIN sobre las columnas indexadas, pero tiene un coste: cada INSERT, UPDATE o DELETE obliga también a mantener el índice al día. Por eso conviene indexar las columnas que se consultan o se unen con frecuencia (por ejemplo, las claves foráneas) y no todas indiscriminadamente.

    Fuentes: PostgreSQL: niveles de aislamiento · MySQL: sintaxis de JOIN · PostgreSQL: introducción a los índices Los conceptos son del estándar SQL; la documentación enlazada es la de PostgreSQL y MySQL.

    Puntos clave

    • Una transacción es indivisible: se completan todas sus operaciones, o ninguna.
    • ACID resume las cuatro propiedades que garantizan transacciones fiables.
    • PL/SQL añade variables, condicionales y bucles a SQL para programar dentro de la base de datos.
    • Un trigger se dispara automáticamente ante un evento (INSERT/UPDATE/DELETE) sobre una tabla.
    • MongoDB guarda documentos tipo JSON, sin el esquema rígido de columnas de una base de datos relacional.

    Ponte a prueba

    ¿Qué significa la 'A' de ACID?

    Atomicidad: la transacción se ejecuta entera o no se ejecuta ninguna de sus partes.

    ¿Para qué sirve un cursor en PL/SQL?

    Para recorrer fila a fila el resultado de una consulta dentro de un bloque PL/SQL.

    ¿Cuál es la diferencia entre un procedimiento y una función en PL/SQL?

    Una función siempre devuelve un valor; un procedimiento no necesariamente.

    ¿Qué tipo de base de datos es MongoDB?

    Una base de datos NoSQL documental, que guarda información como documentos tipo JSON en vez de tablas.
