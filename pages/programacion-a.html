    Programación A

    Primera parte del módulo de Programación: qué es programar, cómo se estructura un programa y las bases del lenguaje Java, hasta llegar a la programación orientada a objetos y la construcción de interfaces gráficas.

    0. Qué es la programación

    Programar es crear un conjunto de instrucciones (código), escritas en un lenguaje que el ordenador puede entender y ejecutar, para resolver un problema o realizar una tarea. Todo programa parte de un problema a resolver y termina en una solución expresada como instrucciones en un lenguaje concreto.

    Pequeña historia de la programación

    Desde el ábaco hasta el software del programa Apollo de la NASA, la idea central no ha cambiado: separar los datos del procedimiento que los manipula. Esa separación es, precisamente, la noción de algoritmo que formuló Ada Lovelace en el siglo XIX junto a Charles Babbage, lo que la convierte en la primera programadora de la historia.

    ¿Sabías que...?

    El código de vuelo del programa Apollo, escrito a mano en ensamblador por el equipo de Margaret Hamilton, ocupaba pilas de listados más altas que una persona. Puedes verlo publicado en GitHub a día de hoy.

    El algoritmo

    Un algoritmo es una secuencia finita y ordenada de pasos que resuelve un problema. Para considerarse un buen algoritmo debe cumplir cinco características: ser finito (número limitado de pasos), estar definido (cada paso claramente especificado), aceptar entradas, producir una salida y hacerlo con eficiencia (tiempo y recursos razonables). Una receta de cocina o el proceso de cambiar el aceite de un coche son algoritmos perfectamente válidos aunque no se ejecuten en un ordenador.

    El pensamiento computacional

    Es el método de resolución de problemas que hay detrás de cualquier algoritmo, y se apoya en cuatro pilares: descomposición (dividir un problema grande en partes manejables), reconocimiento de patrones (detectar similitudes reutilizables), abstracción (quedarse solo con los detalles esenciales) y el propio diseño de algoritmos.

    El proceso de creación de un programa

    De cara al programador, crear un programa sigue siempre el mismo ciclo: análisis del problema → diseño de la solución → implementación (donde se incluyen pruebas y corrección de errores) → programa terminado. Este ciclo se repite constantemente durante el desarrollo, independientemente del lenguaje que se use.

    1. Programación estructurada

    La programación estructurada organiza el código en bloques claros y reutilizables en lugar de instrucciones sueltas. En este bloque se aprende Java escribiendo los primeros programas reales.

    Primer programa en Java

    Todo programa Java necesita una clase con un método main, el punto de entrada por donde arranca la ejecución. El clásico primer ejercicio es mostrar un mensaje por consola:

    public class Main {
  public static void main(String[] args) {
    System.out.println("Hola Mundo!");
  }
}

    Variables

    Una variable es un espacio de almacenamiento con nombre, tipo de dato, valor, alcance y duración, que permite guardar y reutilizar información durante la ejecución. Java tiene tipos primitivos como boolean, int, double o char, además de tipos más complejos como String.

    Operadores

    Los operadores permiten combinar y comparar valores: aritméticos (+ - * / %), unarios (++ --, negación), de asignación (+= -=...), relacionales (== != > <) y lógicos (&& || !). El operador % (módulo) devuelve el resto de una división y es muy útil, por ejemplo, para saber si un número es par. También existe el operador ternario (?:), una forma abreviada de un if-else: int max = (a > b) ? a : b; asigna a max el valor de a si la condición es verdadera, o el de b si es falsa.

    Casting

    El casting convierte un valor de un tipo de dato a otro. Puede ser implícito (Java lo hace solo, al pasar de un tipo más pequeño a uno más grande, como int a double) o explícito (hay que indicarlo a mano entre paréntesis, como (int) 9.78, con riesgo de perder la parte decimal).

    IDE y comentarios

    Un IDE (entorno de desarrollo integrado, como Eclipse, IntelliJ IDEA o Visual Studio) combina editor, compilador, depurador y control de versiones en una sola herramienta, aumentando la productividad. Los comentarios (// para una línea, /* */ para varias, /** */ para generar documentación con Javadoc) no se ejecutan, pero documentan el código para quien lo lea después.

    2. Estructuras de control

    Permiten decidir qué instrucciones se ejecutan y en qué orden. Se dividen en condicionales, de repetición (bucles) y de salto.

    Condicionales

    Ejecutan un bloque de código u otro según se cumpla una condición: if, if-else, if-else-if encadenados, o switch cuando hay muchos valores posibles para una misma variable.

    Bucles (repetición)

    for se usa cuando se sabe de antemano cuántas veces hay que repetir algo; while repite mientras se cumpla una condición (puede no ejecutarse ninguna vez); do-while es igual que while pero garantiza al menos una ejecución.

    Sentencias de salto

    break sale de un bucle o switch antes de tiempo; continue salta a la siguiente iteración sin ejecutar el resto del bloque; return termina un método y, opcionalmente, devuelve un valor.

    Funciones

    Una función (o método) agrupa código reutilizable con nombre, parámetros de entrada, cuerpo y un valor de retorno opcional. Dividir un programa en funciones hace el código más modular y fácil de mantener.

    Recursividad

    Una función recursiva se llama a sí misma para resolver un problema dividiéndolo en versiones más pequeñas del mismo problema, hasta llegar a una condición base que detiene las llamadas (evitando así un desbordamiento de pila). El ejemplo clásico es el factorial:

    public static int factorial(int n) {
    if (n == 0) {
        return 1; // condición base
    } else {
        return n * factorial(n - 1); // llamada recursiva
    }
}

    Palabras reservadas

    Son identificadores predefinidos del lenguaje (class, public, static, if, for, try, new...) que no pueden usarse como nombres de variables porque tienen un significado especial para el compilador.

    Pseudocódigo

    Es una forma de describir un algoritmo en lenguaje natural mezclado con estructuras de control, sin atarse a la sintaxis de ningún lenguaje concreto. Sirve para diseñar la lógica de la solución antes de programarla, y para poder trasladar ese mismo algoritmo a cualquier lenguaje.

    3. Depuración del código

    Depurar es identificar, diagnosticar y corregir errores (bugs) hasta que el programa funciona como se espera; es un proceso continuo, no solo una fase final.

    Qué es un bug (error)

    Los errores se dividen en dos grandes tipos: de compilación (sintaxis incorrecta, variables no declaradas... impiden que el programa llegue a ejecutarse) y de tiempo de ejecución (como dividir por cero o acceder a un índice fuera de rango), que solo aparecen mientras el programa corre.

    Manejo de excepciones

    Una excepción es un evento inesperado que interrumpe el flujo normal del programa. Java gestiona estas situaciones con bloques try / catch / finally: el código que puede fallar va en try, su gestión en catch, y lo que debe ejecutarse siempre (falle o no) va en finally.

    try {
    int resultado = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Error: no se puede dividir por cero.");
}

    La salida de error (System.err)

    System.err es un flujo de salida independiente de System.out, pensado específicamente para mensajes de error, de forma que puedan separarse o redirigirse distinto al resto de la salida del programa.

    Uso de logs

    Un log es un registro cronológico de eventos, avisos y errores de un sistema o aplicación. En Java, la clase Logger permite registrar mensajes con distintos niveles de gravedad (información, advertencia, error grave), muy útil para diagnosticar problemas en producción donde no se puede depurar en directo.

    El depurador

    El depurador (debugger) del IDE permite ejecutar el programa paso a paso: colocar puntos de interrupción (breakpoints), inspeccionar y hasta modificar el valor de las variables en tiempo real, y seguir el flujo exacto de ejecución para localizar la causa real de un fallo.

    Test unitarios

    Son pruebas automatizadas (con frameworks como JUnit) que verifican que una función o método concreto se comporta como se espera, de forma independiente al resto del programa, cubriendo casos normales, límite y de error.

    Toma de tiempos y optimización

    Medir cuánto tarda en ejecutarse un fragmento de código (por ejemplo con System.currentTimeMillis()) permite detectar cuellos de botella y comparar distintas soluciones para elegir la más eficiente.

    4. Programación orientada a objetos I

    La POO organiza el código en torno a "objetos" que agrupan datos y comportamiento, modelando entidades del mundo real (por ejemplo, un Libro con título, autor y número de páginas).

    Qué es una clase

    Una clase es la plantilla que define qué atributos (datos) y qué métodos (comportamientos) tendrán los objetos creados a partir de ella.

    Qué es un objeto

    Un objeto es una instancia concreta de una clase: si Libro es la clase, un ejemplar específico como "El Quijote" es un objeto de esa clase, con sus propios valores para cada atributo.

    Métodos y atributos

    Los atributos almacenan el estado del objeto; los métodos definen su comportamiento (qué puede hacer o qué se puede hacer con él).

    Encapsulación

    Consiste en ocultar los detalles internos de una clase y exponer solo lo necesario a través de métodos públicos (típicamente getters y setters), protegiendo así la integridad de los datos.

    El constructor

    Es un método especial que se ejecuta al crear un objeto con new, y que se usa para inicializar sus atributos con valores iniciales.

    Los paquetes

    Los paquetes (package) agrupan clases relacionadas, evitando conflictos de nombres y organizando el código en un proyecto grande.

    La memoria de un programa

    Java gestiona dos zonas de memoria principales: la pila (stack), donde viven las variables locales y las llamadas a métodos, y el montículo (heap), donde se almacenan los objetos creados con new.

    La recursividad en la memoria

    Cada llamada recursiva añade un nuevo marco a la pila de llamadas; si la recursión no llega nunca a su condición base, la pila se llena y el programa falla con un stack overflow.

    5. GUI y librerías

    Cierra el bloque con las interfaces gráficas y las librerías estándar de Java más habituales para trabajar con entrada/salida, colecciones y generación de informes.

    Qué es UI y UX

    La UI (interfaz de usuario) son los elementos visuales con los que interactúa la persona usuaria; la UX (experiencia de usuario) es la calidad de esa interacción en su conjunto: facilidad de uso, accesibilidad y satisfacción.

    Interfaz de comando y librería JSwing

    Antes de una interfaz gráfica, muchos programas funcionan por línea de comandos (CLI). Swing es la librería clásica de Java para construir interfaces gráficas de escritorio con ventanas, botones y formularios.

    Paquetes java.io, java.util y java.math

    java.io proporciona las clases para leer y escribir datos (ficheros, teclado); java.util incluye colecciones como ArrayList o la clase Random; java.math ofrece operaciones matemáticas más allá de los operadores básicos.

    Manejo de XML con JAXB y creación de informes con JasperReports

    JAXB permite convertir automáticamente objetos Java a XML y viceversa. JasperReports es una librería para generar informes (PDF, Excel...) a partir de los datos de la aplicación.

    Recursividad y StackOverflowError

    Cuando una función recursiva no tiene caso base (o la recursión es demasiado profunda), la pila de llamadas se llena y Java lanza un StackOverflowError.

    // Esto causa StackOverflowError
public void funcionRecursiva() {
    funcionRecursiva(); // se llama a sí misma sin condición de parada
}

    Se evita asegurando siempre un caso base y, si el problema es puramente iterativo, prefiriendo un bucle a la recursión.

    JAXB convierte objetos Java a XML (marshaling) y XML a objetos Java (unmarshaling):

    @XmlElement private String nombre;
    @XmlElement private int edad;

// <persona><nombre>Carlos</nombre><edad>30</edad></persona>

    Rangos de los tipos primitivos y dinero con BigDecimal

    Cada tipo entero tiene un tamaño fijo y, con él, un rango de valores: byte (8 bits) va de -128 a 127, short (16 bits) de -32.768 a 32.767, int (32 bits) de -231 a 231-1 y long (64 bits) de -263 a 263-1. Para decimales existen float y double, pero Oracle avisa de que nunca deben usarse para valores exactos como el dinero, porque representan los números de forma aproximada. Para esos casos se usa la clase java.math.BigDecimal.

    System.out.println(0.1 + 0.2);   // 0.30000000000000004 (double: aproximado)

BigDecimal a = new BigDecimal("0.1");
BigDecimal b = new BigDecimal("0.2");
System.out.println(a.add(b));    // 0.3 (exacto)

    Excepciones comprobadas y no comprobadas

    Java distingue tres clases de problemas. Las excepciones comprobadas (checked) representan condiciones razonables que un programa bien hecho debería prever, como un archivo que no existe: el compilador obliga a capturarlas con try/catch o a declararlas con throws (el requisito «catch or specify»). Los errores (Error) son condiciones externas graves que el programa normalmente no puede resolver, y las excepciones de ejecución (RuntimeException) suelen indicar fallos de programación, como acceder a un índice inexistente. Errores y excepciones de ejecución forman las no comprobadas (unchecked) y el compilador no obliga a tratarlas.

    String es inmutable, StringBuilder no

    Un objeto String no se puede modificar una vez creado: cada operación que parece cambiarlo (concatenar, pasar a mayúsculas) devuelve un objeto nuevo. Cuando hay que construir un texto a base de muchas concatenaciones, por ejemplo dentro de un bucle, StringBuilder es más eficiente porque es mutable y añade contenido sobre el mismo objeto.

    Puntos clave

    • Un algoritmo debe ser finito, definido, aceptar entradas, producir salida y ser eficiente.
    • La programación estructurada organiza el código en bloques reutilizables en vez de instrucciones sueltas.
    • Las estructuras de control (condicionales, bucles, saltos) deciden qué se ejecuta y en qué orden.
    • La recursividad necesita siempre una condición base para no desbordar la pila.
    • Depurar no es solo corregir errores al final: es un proceso continuo con logs, tests y el depurador del IDE.
    • La POO modela el mundo real con clases y objetos: atributos + métodos + encapsulación.

    Ponte a prueba

    ¿Cuál es la diferencia entre un error de compilación y uno de tiempo de ejecución?

    El de compilación impide que el programa llegue a ejecutarse (sintaxis, variables no declaradas); el de tiempo de ejecución ocurre mientras el programa corre (dividir por cero, índice fuera de rango).

    ¿Qué evita que una función recursiva entre en bucle infinito?

    La condición base: el caso más simple del problema que la función puede resolver directamente sin volver a llamarse.

    ¿Qué diferencia hay entre a++ y ++a?

    a++ devuelve el valor de a y luego lo incrementa; ++a lo incrementa primero y luego devuelve el nuevo valor.

    ¿Para qué sirve la encapsulación en POO?

    Para ocultar los detalles internos de una clase y exponer solo lo necesario mediante métodos públicos (getters/setters), protegiendo la integridad de los datos.

    ¿Qué diferencia hay entre System.out y System.err?

    Ambos imprimen por consola, pero System.err es un flujo independiente pensado para mensajes de error, que se puede separar o redirigir distinto al resto de la salida.
