    Fundamentos de Java

    Apunte compacto y muy práctico de Java: desde instalar el JDK hasta la orientación a objetos, pensado como chuleta de sintaxis más que como libro de texto.

    Instalación y entorno

    Para programar en Java hacen falta dos piezas: el JDK (Java Development Kit), que incluye el compilador y la máquina virtual, y el JRE, que es la máquina virtual necesaria para ejecutar programas ya compilados.

    • JAVA_HOME: variable de entorno del sistema que indica dónde está instalado el JDK.
    • PATH: se amplía con la ruta al JDK para poder invocar java y javac desde cualquier carpeta.
    • Probar la instalación con java -version desde la terminal confirma que todo está bien configurado.
    ¿Sabías que...?

    El lema de Java desde su creación en 1995 es "write once, run anywhere" (escribe una vez, ejecuta en cualquier lugar): el mismo bytecode compilado corre igual en Windows, Linux o macOS gracias a la máquina virtual (JVM).

    Sintaxis básica

    Todo programa Java vive dentro de una clase, y su ejecución empieza en el método main; cada instrucción termina con punto y coma.

    • Comentarios: // de una línea, /* */ de varias.
    • Constantes (final) frente a variables, que sí pueden cambiar de valor.
    • Tipos primitivos (int, double, boolean, char...) almacenan el valor directamente; los tipos objeto (String, clases propias) almacenan una referencia.
    • Operadores aritméticos, relacionales y lógicos para construir expresiones.

    Estructuras de control y E/S

    Condicionales (if/else, switch) deciden qué código se ejecuta; repetitivas (for, while, do-while) repiten un bloque. Para entrada de datos por teclado se usa la clase Scanner del paquete java.util. La organización en la API de Java agrupa estas clases en paquetes (java.lang, java.util...) que se importan con import.

    Orientación a objetos

    Bloque central del documento: cómo modelar entidades con clases y objetos.

    • Clase, objeto y estructura de una clase: la clase es la plantilla (atributos + métodos); el objeto es cada instancia concreta creada con new.
    • Atributos, constructor y métodos: los atributos guardan el estado, el constructor inicializa un objeto recién creado, y los métodos definen su comportamiento.
    • Getters y setters: métodos públicos para leer y modificar atributos privados de forma controlada (encapsulación).
    • Ámbito de las variables: dónde es visible una variable (dentro de un método, de una clase o global); la signatura de un método es su nombre más el tipo y orden de sus parámetros.
    • Sobrecarga de nombres: varios métodos pueden compartir nombre si difieren en su lista de parámetros.
    • Creación de un objeto y clase principal: la clase con el método main es el punto de arranque del programa.
    • Igualdad vs. identidad: == compara si dos referencias apuntan al mismo objeto en memoria, mientras que .equals() compara si su contenido es equivalente.
    • Asignación entre objetos: al asignar un objeto a otra variable se copia la referencia, no el objeto; ambas variables acaban apuntando al mismo objeto en memoria.

    Cadenas, colecciones y utilidades

    • Cadenas de texto (String): inmutables en Java, con métodos como length(), substring() o toUpperCase().
    • Arrays: colecciones de tamaño fijo; ArrayList: lista dinámica que puede crecer o encogerse; Random: generación de números aleatorios.
    • Conversión de tipos: castings explícitos/implícitos entre tipos primitivos, y métodos como Integer.parseInt() para convertir texto a número.
    • Paquetes para organizar clases relacionadas, y Javadoc (comentarios /** */) para generar documentación automática del código.

    Polimorfismo, herencia y modificadores

    • Herencia (extends): una clase reutiliza atributos y métodos de otra.
    • Polimorfismo: una referencia de la superclase puede comportarse de forma distinta según el objeto real que contenga, especialmente al sobreescribir métodos (@Override).
    • Modificadores de acceso: public (accesible desde cualquier sitio), private (solo dentro de la clase), protected (clase, mismo paquete y subclases) y el acceso por defecto o package (solo dentro del mismo paquete).

    Errores comunes a evitar

    • Olvidar el punto y coma al final de la instrucción.
    • No cerrar llaves, paréntesis o comillas.
    • Confundir = (asignación) con == (comparación).
    • Dividir por cero, que lanza ArithmeticException con enteros.
    • Crear bucles infinitos por una condición que nunca se cumple.
    • Escribir funciones recursivas sin caso base.

    Buenas prácticas

    • Usar nombres descriptivos para variables y funciones.
    • Indentar bien y comentar solo lo que no sea evidente.
    • Evitar código duplicado sacándolo a funciones.
    • Probar el código con distintos casos de entrada, incluidos los límites.

    La recursividad consume más memoria que la solución iterativa equivalente, porque cada llamada ocupa un hueco en la pila.

    Del código fuente al bytecode

    Un programa Java no se compila directamente a código de máquina: el compilador javac traduce los archivos .java a bytecode guardado en archivos .class, y la máquina virtual de Java (JVM) lo ejecuta. Como el bytecode es el mismo para todos, se puede ejecutar en cualquier sistema que tenga una JVM, y de ahí viene la portabilidad de Java entre sistemas operativos.

    Enumerados (enum)

    Un enum define un tipo con un conjunto fijo de constantes, como los días de la semana o los estados de un pedido. Por convención sus nombres van en mayúsculas. Se usan cuando todos los valores posibles se conocen en tiempo de compilación, y son más seguros que usar números o textos sueltos porque el compilador rechaza cualquier valor que no sea una de las constantes. Un enum también puede tener campos y métodos, y el método values() devuelve todas sus constantes.

    Autoboxing y clases envoltorio

    Cada tipo primitivo tiene una clase envoltorio (int → Integer, double → Double, boolean → Boolean...). El autoboxing es la conversión automática de un primitivo a su envoltorio, y el unboxing la inversa. Es lo que permite, por ejemplo, guardar números en una List<Integer>, ya que las colecciones solo admiten objetos.

    Puntos clave

    • El JDK incluye el compilador; el JRE es lo mínimo necesario para ejecutar un programa ya compilado.
    • Los tipos primitivos guardan el valor directamente; los tipos objeto guardan una referencia.
    • == compara referencias; .equals() compara contenido.
    • Sobrecargar un método significa repetir su nombre variando los parámetros; sobreescribir significa redefinirlo en una subclase.
    • Los modificadores de acceso (public/private/protected/package) controlan qué puede ver cada parte del código.

    Ponte a prueba

    ¿Cuál es la diferencia entre el JDK y el JRE?

    El JDK incluye el compilador y las herramientas de desarrollo; el JRE es solo la máquina virtual necesaria para ejecutar programas ya compilados.

    ¿Qué diferencia hay entre == y .equals() con objetos?

    == comprueba si dos referencias apuntan al mismo objeto en memoria; .equals() comprueba si su contenido es equivalente.

    ¿Qué es la sobrecarga de métodos?

    Definir varios métodos con el mismo nombre pero distinta lista de parámetros.

    ¿Qué modificador de acceso permite ver un miembro solo dentro del mismo paquete?

    El acceso por defecto (sin escribir ningún modificador), también llamado package-private.
