    Docker

    Contenedores para empaquetar una aplicación con todo lo que necesita para ejecutarse igual en cualquier máquina, evitando el clásico "en mi ordenador funciona".

    0. Qué es un contenedor

    Un contenedor empaqueta una aplicación junto con sus dependencias (librerías, variables de entorno, versión del lenguaje) en una unidad aislada y reproducible. A diferencia de una máquina virtual, un contenedor no incluye un sistema operativo completo: comparte el kernel del sistema operativo anfitrión, lo que lo hace mucho más ligero y rápido de arrancar.

    ¿Sabías que...?

    El nombre y el logo de Docker (una ballena cargando cajas) hacen referencia a los contenedores de transporte marítimo: igual que un contenedor estándar se puede cargar en cualquier barco o camión sin importar lo que lleve dentro, un contenedor Docker se ejecuta igual en cualquier máquina.

    Imagen vs. contenedor

    Una imagen es la plantilla de solo lectura (el "molde") con la aplicación y sus dependencias; un contenedor es una instancia en ejecución de esa imagen. De la misma imagen se pueden lanzar varios contenedores independientes.

    1. Imágenes y el Dockerfile

    Un Dockerfile es un archivo de texto con las instrucciones para construir una imagen paso a paso. Cada instrucción añade una capa a la imagen, y Docker reutiliza las capas que no han cambiado para acelerar construcciones posteriores.

    FROM node:20
WORKDIR /app
COPY . .
RUN npm install
CMD ["npm", "start"]

    Instrucciones más comunes

    FROM define la imagen base de partida; COPY copia archivos del proyecto dentro de la imagen; RUN ejecuta un comando durante la construcción (como instalar dependencias); CMD indica el comando por defecto al arrancar el contenedor. docker build -t nombre . construye la imagen a partir del Dockerfile.

    Docker Hub y otros registries

    Un registry es un almacén de imágenes listas para descargar, como FROM node:20 hace en el ejemplo anterior. Docker Hub es el registry público por defecto, con imágenes oficiales de la mayoría de lenguajes y bases de datos; docker pull imagen la descarga, y docker push sube una imagen propia (previo docker login). También existen registries privados, propios de cada empresa o de proveedores cloud.

    2. Ejecutar contenedores

    docker run nombre-imagen crea y arranca un contenedor a partir de una imagen; docker ps lista los contenedores en ejecución; docker stop id lo detiene y docker rm id lo elimina.

    Puertos y variables de entorno

    Un contenedor está aislado de la red del host por defecto: -p 8080:80 mapea el puerto 80 del contenedor al 8080 de la máquina para poder acceder desde fuera. -e VARIABLE=valor pasa variables de entorno al contenedor, útil para configuración sin tocar la imagen (como credenciales de una base de datos).

    3. Volúmenes y persistencia

    Un contenedor es efímero por naturaleza: si se elimina, se pierde todo lo que se haya escrito dentro de él. Para persistir datos (los archivos de una base de datos, por ejemplo) se usan volúmenes, gestionados por Docker y que sobreviven aunque el contenedor se borre y se vuelva a crear.

    Bind mounts

    Un bind mount es parecido pero conecta directamente una carpeta del host con una del contenedor (por ejemplo, el código fuente durante el desarrollo, para ver los cambios sin reconstruir la imagen), mientras que un volumen lo gestiona Docker de forma independiente del sistema de archivos del host.

    4. Docker Compose

    Una aplicación real suele necesitar varios contenedores a la vez (por ejemplo, la aplicación y su base de datos). Docker Compose permite definir todos esos servicios en un único archivo docker-compose.yml y levantarlos juntos con un solo comando: docker compose up.

    Por qué usarlo

    Evita tener que recordar y encadenar a mano varios comandos docker run con sus puertos, volúmenes y redes; además, describe la infraestructura del proyecto como código, versionable junto al resto del repositorio.

    Puntos clave

    • Un contenedor comparte el kernel del host (a diferencia de una VM), por eso es más ligero.
    • Una imagen es la plantilla; un contenedor es una instancia en ejecución de esa imagen.
    • El Dockerfile define cómo construir la imagen, capa a capa (FROM, COPY, RUN, CMD).
    • Los contenedores son efímeros: los volúmenes se usan para persistir datos entre reinicios.
    • Docker Compose orquesta varios contenedores relacionados desde un único archivo YAML.

    Ponte a prueba

    ¿Qué diferencia hay entre un contenedor y una máquina virtual?

    El contenedor comparte el kernel del sistema operativo anfitrión y no incluye un SO completo, por lo que es mucho más ligero y rápido de arrancar que una máquina virtual.

    ¿Qué diferencia hay entre una imagen y un contenedor?

    La imagen es la plantilla de solo lectura con la aplicación y sus dependencias; el contenedor es una instancia en ejecución de esa imagen. De una misma imagen pueden lanzarse varios contenedores.

    ¿Por qué se necesitan volúmenes si ya se pueden guardar archivos dentro del contenedor?

    Porque un contenedor es efímero: si se elimina, se pierde todo lo escrito dentro. Los volúmenes persisten los datos independientemente del ciclo de vida del contenedor.

    ¿Para qué sirve Docker Compose?

    Para definir y levantar varios contenedores relacionados (por ejemplo, aplicación y base de datos) desde un único archivo docker-compose.yml, en vez de encadenar varios comandos docker run a mano.
