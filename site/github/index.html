    GitHub

    La plataforma de alojamiento de repositorios Git más usada, con herramientas de colaboración: pull requests, issues y automatización con Actions. No es la única (existen GitLab, Bitbucket...), pero es el estándar de facto en el software de código abierto.

    0. GitHub no es lo mismo que Git

    Git es la herramienta de control de versiones que se ejecuta en tu ordenador; GitHub es un servicio que aloja repositorios Git en la nube y añade una capa de colaboración por encima: interfaz web, pull requests, gestión de tareas y automatización. Un repositorio de GitHub sigue siendo, por debajo, un repositorio Git normal.

    ¿Sabías que...?

    Microsoft compró GitHub en 2018 por 7.500 millones de dólares, pero la plataforma sigue funcionando de forma independiente y sigue siendo el punto de encuentro de la inmensa mayoría de proyectos open source.

    Alternativas a GitHub

    GitLab (que además se puede instalar en un servidor propio) y Bitbucket son las alternativas más usadas; todas hablan el mismo protocolo Git por debajo, así que un mismo repositorio local puede, en teoría, subirse a cualquiera de ellas.

    1. Repositorios remotos

    Un repositorio en GitHub puede ser público (cualquiera lo ve) o privado (solo las personas invitadas). Al crearlo, GitHub ofrece generar automáticamente un README.md (la portada del proyecto), un .gitignore según el lenguaje y un archivo de licencia.

    Fork

    Hacer un fork crea una copia independiente de un repositorio ajeno en tu propia cuenta. Es el mecanismo habitual para contribuir a un proyecto en el que no tienes permisos de escritura directos: haces fork, cambias tu copia y luego propones esos cambios al original mediante un pull request.

    GitHub Pages

    Permite publicar gratis un sitio web estático directamente desde un repositorio, sin contratar ningún hosting: activándolo en la configuración del repositorio, el contenido de una rama (normalmente main o una carpeta docs/) queda accesible en una URL del tipo usuario.github.io/repositorio. Es la forma más rápida de publicar un proyecto de HTML/CSS/JS sin backend.

    2. Pull requests

    Un pull request (PR) es una propuesta para fusionar los cambios de una rama dentro de otra (normalmente hacia main), acompañada de una descripción, comentarios y revisión de código antes de aceptarla. Es el mecanismo central de colaboración en GitHub.

    Flujo típico

    Crear una rama para la tarea → hacer commits en ella → subirla con git push → abrir un pull request desde esa rama hacia main → otra persona revisa el código y deja comentarios → cuando está aprobado, se fusiona (merge) y la rama puede borrarse.

    3. Issues y proyectos

    Los issues son el sistema de seguimiento de tareas y errores de GitHub: cada uno describe un problema o una funcionalidad pendiente, y se le pueden asignar personas, etiquetas (labels) como bug o enhancement, y un hito (milestone) para agruparlo dentro de una entrega.

    GitHub Projects

    Es un tablero tipo Kanban integrado en el repositorio, donde los issues y pull requests se organizan en columnas (por ejemplo, "Por hacer", "En progreso", "Hecho") para visualizar el estado del trabajo de un vistazo.

    4. GitHub Actions

    GitHub Actions permite automatizar tareas del repositorio (ejecutar tests, desplegar la aplicación, revisar el estilo del código) cada vez que ocurre un evento, como un push o la apertura de un pull request. Cada automatización se define en un archivo YAML dentro de la carpeta .github/workflows/.

    name: Tests
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm test

    Cuándo usarlo

    Es habitual usarlo para integración continua (CI): que las pruebas se ejecuten automáticamente en cada cambio, antes de permitir fusionar un pull request, evitando que se rompa algo que ya funcionaba.

    Puntos clave

    • GitHub aloja repositorios Git y añade colaboración (PRs, issues, Actions); Git funciona igual sin GitHub.
    • Un fork crea una copia propia de un repositorio ajeno, base habitual para contribuir sin permisos directos.
    • Un pull request propone fusionar una rama y permite revisar el código antes de aceptarlo.
    • Los issues siguen tareas y errores; GitHub Projects los organiza en un tablero Kanban.
    • GitHub Actions automatiza tareas (tests, despliegues) a partir de eventos del repositorio, definidas en YAML.

    Ponte a prueba

    ¿Qué diferencia hay entre Git y GitHub?

    Git es la herramienta de control de versiones que corre en tu ordenador; GitHub es una plataforma que aloja repositorios Git en remoto y añade colaboración (pull requests, issues, Actions) por encima.

    ¿Para qué se usa un fork?

    Para crear una copia propia de un repositorio ajeno cuando no tienes permisos de escritura directos, y así poder proponer cambios mediante un pull request.

    ¿Qué es un pull request?

    Una propuesta para fusionar los cambios de una rama en otra, que permite revisar y comentar el código antes de aceptarla.

    ¿Para qué sirve GitHub Actions?

    Para automatizar tareas del repositorio (como ejecutar tests o desplegar la aplicación) cada vez que ocurre un evento, como un push, definiendo el flujo en un archivo YAML.
