    HTTP — Chuleta

    Referencia rápida de cómo hablan el navegador y el servidor: la forma de una petición y una respuesta, los métodos, los códigos de estado y las cabeceras que más se ven.

    Petición y respuesta

    Una petición lleva una línea inicial (método, destino y versión), cabeceras, una línea vacía y, a veces, un cuerpo:

    POST /users HTTP/1.1
Host: example.com
Content-Type: application/json

{"name": "Ana"}

    Una respuesta lleva una línea de estado (versión, código y texto), cabeceras, una línea vacía y, a veces, un cuerpo:

    HTTP/1.1 201 Created
Content-Type: application/json
Location: http://example.com/users/123

{"id": 123, "name": "Ana"}

    Las cabeceras son pares Nombre: valor y no distinguen mayúsculas en el nombre.

    Métodos

    MétodoPara qué sirveSeguroIdempotente
    GETPedir un recurso. Solo lee datos y no debe llevar cuerpoSíSí
    POSTEnviar datos al recurso, normalmente para crear algo o provocar un cambioNoNo
    PUTReemplazar el recurso por completo con el cuerpo enviadoNoSí
    PATCHAplicar una modificación parcialNoNo
    DELETEBorrar el recursoNoSí
    HEADComo GET, pero solo devuelve las cabecerasSíSí
    • Seguro: no cambia nada en el servidor. Idempotente: repetir la misma petición produce el mismo efecto que hacerla una vez, así que se puede reintentar sin miedo.
    • Repetir un DELETE puede devolver un código distinto (la primera vez éxito y después 404, porque el recurso ya no existe), aunque el efecto sea el mismo.

    Códigos de estado

    GrupoSignificado
    1xxInformativas
    2xxÉxito
    3xxRedirección
    4xxError del cliente
    5xxError del servidor
    CódigoSignificado
    200La petición ha tenido éxito
    201Éxito y se ha creado un recurso nuevo
    204Sin contenido que devolver
    301El recurso se ha movido de forma permanente
    302El recurso se ha movido de forma temporal
    304No ha cambiado: se puede seguir usando la copia en caché
    400La petición no se puede procesar por un error del cliente
    401No autenticado: faltan credenciales válidas
    403Prohibido: el servidor rechaza dar el recurso al cliente
    404No se encuentra el recurso
    409La petición entra en conflicto con el estado actual del servidor
    429Demasiadas peticiones en poco tiempo
    500Error interno del servidor
    502Una pasarela recibió una respuesta no válida
    503El servidor no está listo para atender la petición

    401 frente a 403: un 401 significa «no sé quién eres» (faltan credenciales válidas); un 403 significa «sé quién eres, pero no tienes permiso».

    Cabeceras habituales

    CabeceraQué indica
    Content-TypeEl tipo de contenido del cuerpo (por ejemplo application/json)
    Content-LengthEl tamaño del cuerpo, en bytes
    AcceptLos tipos de datos que el cliente acepta recibir
    AuthorizationLas credenciales para autenticarse en el servidor
    Cache-ControlDirectivas de caché, en peticiones y respuestas
    LocationLa URL a la que redirigir, o la del recurso recién creado
    User-AgentQué programa hace la petición (navegador, versión, sistema)
    Cookie / Set-CookieLas cookies que el cliente envía, y las que el servidor le manda guardar

    Ejemplo: una API REST

    Convención habitual: la ruta nombra el recurso y el método indica la acción.

    AcciónPeticiónRespuesta típica
    Listar usuariosGET /users200 y la lista
    Ver un usuarioGET /users/123200, o 404 si no existe
    Crear un usuarioPOST /users201 y su Location
    Reemplazar un usuarioPUT /users/123200 o 204
    Modificar parte de un usuarioPATCH /users/123200 o 204
    Borrar un usuarioDELETE /users/123204 (o 200)

    Errores frecuentes

    • Confundir 401 y 403. Sin credenciales válidas es 401; con credenciales válidas pero sin permiso es 403.
    • Usar GET para modificar datos. GET debe ser solo lectura y seguro; para cambiar algo usa POST, PUT, PATCH o DELETE.
    • Enviar JSON sin Content-Type. El servidor necesita saber el tipo del cuerpo: Content-Type: application/json.
    • Devolver 200 con un mensaje de error dentro. El código de estado debe reflejar el resultado real.
    • Confundir 4xx con 5xx. Un 4xx es un fallo de la petición (del cliente); un 5xx, del servidor.
