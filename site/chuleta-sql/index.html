    SQL — Chuleta

    Referencia rápida de las sentencias SQL que más se usan. Sin teoría: solo la sintaxis y lo que suele olvidarse. Los ejemplos usan la sintaxis de MySQL y PostgreSQL.

    Consultar datos (SELECT)

    SELECT columna1, columna2      -- qué columnas (* = todas)
FROM tabla                     -- de qué tabla
WHERE condición                -- qué filas (opcional)
ORDER BY columna1 DESC         -- en qué orden (ASC por defecto)
LIMIT 10;                      -- cuántas filas
    • SELECT DISTINCT columna elimina las filas duplicadas del resultado.
    • columna AS alias da otro nombre a una columna en el resultado.
    • LIMIT existe en MySQL y PostgreSQL; otros motores usan otra sintaxis (por ejemplo, TOP en SQL Server).

    Modificar datos (INSERT, UPDATE, DELETE)

    INSERT INTO clientes (nombre, email)
VALUES ('Ana', 'ana@ejemplo.com'),
       ('Luis', 'luis@ejemplo.com');    -- varias filas a la vez

UPDATE clientes
SET email = 'nuevo@ejemplo.com'
WHERE id_cliente = 3;                   -- sin WHERE cambia TODAS las filas

DELETE FROM clientes
WHERE id_cliente = 3;                   -- sin WHERE borra TODAS las filas

    Agrupar y resumir

    SELECT ciudad, COUNT(*) AS total, AVG(edad) AS edad_media
FROM clientes
WHERE activo = 1              -- filtra filas ANTES de agrupar
GROUP BY ciudad
HAVING COUNT(*) > 5           -- filtra grupos DESPUÉS de agrupar
ORDER BY total DESC;
    • Funciones de agregación: COUNT, SUM, AVG, MIN, MAX.
    • COUNT(*) cuenta todas las filas; COUNT(columna) solo las que no son nulas. SUM, AVG, MIN y MAX también ignoran los nulos.
    • Toda columna del SELECT que no sea una función de agregación debe estar en el GROUP BY.

    Unir tablas (JOIN)

    SELECT c.nombre, p.total
FROM clientes c
INNER JOIN pedidos p ON p.id_cliente = c.id_cliente;
    TipoDevuelve
    INNER JOINSolo las filas que tienen pareja en ambas tablas
    LEFT JOINTodas las de la izquierda; sin pareja, columnas de la derecha a NULL
    RIGHT JOINTodas las de la derecha; sin pareja, columnas de la izquierda a NULL

    Para encontrar filas sin correspondencia: LEFT JOIN y filtrar con WHERE tabla_derecha.clave IS NULL.

    Crear y cambiar la estructura

    CREATE TABLE clientes (
  id_cliente INT AUTO_INCREMENT PRIMARY KEY,   -- AUTO_INCREMENT es de MySQL
  nombre     VARCHAR(80) NOT NULL,
  email      VARCHAR(120) UNIQUE,
  alta       DATE
);

CREATE TABLE pedidos (
  id_pedido  INT PRIMARY KEY,
  id_cliente INT NOT NULL,
  total      DECIMAL(10,2),
  FOREIGN KEY (id_cliente) REFERENCES clientes(id_cliente)
);

ALTER TABLE clientes ADD COLUMN telefono VARCHAR(20);
ALTER TABLE clientes DROP COLUMN telefono;
DROP TABLE pedidos;

    En qué orden se evalúa una consulta

    Se escribe empezando por SELECT, pero lógicamente se evalúa así:

    FROM / JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT

    Por eso un alias definido en el SELECT no se puede usar en el WHERE.

    Errores frecuentes

    • = NULL no funciona. Un valor nulo no es igual a nada, ni siquiera a otro nulo: usa IS NULL.
    • UPDATE o DELETE sin WHERE. Afecta a todas las filas de la tabla. Escribe el WHERE primero.
    • WHERE con una función de agregación. No se puede: para filtrar por el resultado de COUNT o SUM se usa HAVING.
    • Columna fuera del GROUP BY. Si no es una agregación, hay que agruparla o quitarla del SELECT.
    • Comillas. El texto y las fechas van entre comillas simples ('Madrid'); los números, sin comillas.
