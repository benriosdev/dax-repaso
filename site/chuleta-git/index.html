    Comandos de Git — Chuleta

    Referencia rápida de los comandos de Git que más se usan, organizados por lo que quieres hacer. Para entender cómo funciona Git, mira la página de Git en Herramientas.

    Empezar

    git config --global user.name "Tu Nombre"
git config --global user.email "tu@correo.com"

git init                    # crear un repositorio en la carpeta actual
git clone <url>             # copiar un repositorio remoto

    El ciclo diario

    git status                  # qué ha cambiado
git diff                    # ver los cambios aún sin preparar
git add archivo.txt         # preparar un archivo (git add . = todos)
git commit -m "Añade el formulario de contacto"
git log --oneline           # historial en una línea por commit

    Un buen mensaje de commit se escribe en imperativo («Añade…», «Corrige…») y explica qué cambia y, si no es evidente, por qué.

    Ramas

    git branch                  # listar las ramas
git switch nombre           # cambiar a una rama existente
git switch -c nueva         # crear una rama y cambiar a ella
git switch -                # volver a la rama anterior
git merge nombre            # fusionar esa rama en la actual
git branch -d nombre        # borrar una rama ya fusionada

    Deshacer cambios

    Qué comando usar depende de dónde está el cambio que quieres deshacer:

    SituaciónComando
    Descartar los cambios de un archivo sin preparargit restore archivo
    Sacar un archivo del área de preparación (sigue modificado)git restore --staged archivo
    Corregir el último commit, si aún no lo has subidogit commit --amend
    Deshacer el último commit, conservando los cambios preparadosgit reset --soft HEAD~1
    Deshacer el último commit y sacar los cambios de la preparación (siguen en los archivos)git reset HEAD~1
    Deshacer un commit ya publicado, sin reescribir el historialgit revert <commit>
    Guardar cambios a medias para cambiar de tareagit stash (después git stash pop)
    • git reset mueve la rama a otro commit. Con --soft el índice y los archivos quedan igual; por defecto (--mixed) se actualiza el índice y los archivos no cambian; con --hard se sobrescriben también los archivos.
    • git reset --hard descarta los cambios de forma definitiva, incluso puede sobrescribir archivos sin seguimiento. No lo uses sobre commits que ya has compartido.
    • git revert no borra nada: crea un commit nuevo que invierte el efecto del anterior.
    • git stash list muestra los guardados; git stash apply recupera uno sin borrarlo de la lista y git stash pop lo recupera y lo borra.

    Trabajar con remotos

    git remote add origin <url>   # asociar un remoto (suele llamarse origin)
git remote -v                  # ver los remotos configurados
git push -u origin main        # subir la rama y recordar su destino
git push                       # subir los commits (tras el primer push -u)
git fetch                      # traer los cambios sin integrarlos
git pull                       # traerlos e integrarlos en la rama actual

    git pull equivale a un git fetch seguido de la integración de esos cambios en tu rama.

    Errores frecuentes

    • Olvidar git add. Solo entra en el commit lo que has preparado. Comprueba con git status.
    • Commitear archivos que no deben subirse (claves, .env, dependencias). Añádelos a .gitignore antes del primer commit.
    • Reescribir historial ya compartido. Con commits ya subidos, deshaz con git revert, no con reset ni --amend.
    • Hacer pull con cambios sin guardar. Haz commit o git stash antes.
