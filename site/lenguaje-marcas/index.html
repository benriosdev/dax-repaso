    Lenguaje de Marcas

    De los lenguajes de marcas en general al desarrollo web real: HTML, CSS, JavaScript, XML y su uso en sistemas de gestión empresarial como Odoo.

    1. Qué son los lenguajes de marcas

    Un lenguaje de marcas combina el contenido con etiquetas (marcas) que describen su estructura o su formato, en lugar de código de programación tradicional. XML es el más genérico: no define etiquetas fijas, sino que permite crear las propias según lo que se necesite describir.

    <libro>
  <titulo>El Quijote</titulo>
  <autor>Cervantes</autor>
</libro>

    Un documento XML está bien formado cuando respeta la sintaxis básica (una única raíz, etiquetas que se cierran correctamente y están bien anidadas

    ¿Sabías que...?

    Tim Berners-Lee creó HTML en 1991 con apenas una veintena de etiquetas. La versión actual, HTML5, tiene más de 100, muchas de ellas semánticas (<article>, <nav>) pensadas para que el propio código describa el significado del contenido.

    ). El espacio de nombres (namespace) evita que se mezclen etiquetas con el mismo nombre pero de significados distintos al combinar varios vocabularios XML en un mismo documento.

    2. Lenguajes de marcas en entornos web

    HTML es el lenguaje de marcas específico para construir páginas web, con un conjunto fijo de etiquetas (a diferencia de XML). Un documento HTML5 se estructura con una cabecera <head> (metadatos, título) y un cuerpo <body> (el contenido visible), organizado con etiquetas semánticas como <header>, <nav>, <main> o <footer>. Cada etiqueta puede llevar atributos (como class o href) que añaden información o comportamiento al elemento.

    3. Hojas de estilo

    CSS separa el contenido (HTML) de su presentación visual. Una regla CSS asocia un selector (a qué elementos afecta) con una lista de propiedades y valores:

    .tarjeta {
  background-color: #1a1b1f;
  border-radius: 8px;
  padding: 1rem;
}

    El diseño responsive (con unidades relativas y media queries) adapta la web a distintos tamaños de pantalla; los layouts avanzados como Flexbox y Grid organizan elementos en filas y columnas sin depender de trucos antiguos. Bulma es un framework CSS (como Bootstrap) que ofrece componentes ya maquetados para no escribir todo el CSS desde cero.

    4. Lenguajes de script

    JavaScript es el lenguaje que añade interactividad a una página web, ejecutándose en el propio navegador. El DOM (Document Object Model) es la representación en memoria de la página como un árbol de objetos, que JavaScript puede leer y modificar para cambiar el contenido sin recargar la página. También soporta programación orientada a objetos y trabajo asíncrono (con promises o async/await) para operaciones que tardan, como peticiones a un servidor, sin bloquear el resto de la página. Frameworks como React, Vue o Angular se construyen encima de JavaScript para estructurar aplicaciones web más grandes.

    Cada etiqueta HTML es un nodo del árbol DOM; JavaScript puede acceder y modificar cualquiera de ellos.

    5. XML

    Profundiza en el ciclo de vida de un documento XML: crear descripciones (esquemas o DTD que definen qué etiquetas y estructura son válidas), validar un documento contra ese esquema, y convertir/adaptar XML a otros formatos (por ejemplo a HTML) mediante hojas de transformación como XSLT.

    6. Gestión y almacenamiento de información en XML

    XML puede guardarse en ficheros sueltos, en bases de datos específicas para XML, o integrarse dentro de bases de datos relacionales que ofrecen tipos de columna y funciones propias para consultar contenido XML directamente con SQL, sin tener que parsearlo aparte en la aplicación.

    7. Sistemas de gestión empresarial

    Un ERP (Enterprise Resource Planning) integra en un único sistema los procesos de una empresa (inventario, contabilidad, recursos humanos...); un CRM (Customer Relationship Management) se centra específicamente en la relación con los clientes (contactos, oportunidades de venta, atención al cliente). Odoo se usa como caso práctico: se instala y configura como ERP, se generan informes, se integra con herramientas ofimáticas y se configura también como CRM dentro de la misma plataforma. Todo ello se apoya en la inteligencia de negocio (BI): analizar los datos generados por la empresa para apoyar decisiones.

    8. Próximos pasos

    Cierre del módulo apuntando a TypeScript como siguiente paso: un superconjunto de JavaScript que añade tipado estático (declarar de antemano si una variable es number, string...), lo que ayuda a detectar errores antes de ejecutar el código. El código TypeScript se transpila (convierte) a JavaScript normal antes de llegar al navegador.

    var, let y const

    Alcance¿Reasignable?Uso
    varFunciónSíEvitar (código antiguo)
    letBloque {}SíSolo si el valor va a cambiar
    constBloque {}NoPor defecto

    Si usas let o const antes de declararlas, JavaScript lanza un error: es la Temporal Dead Zone. Con var no hay error, solo undefined. Ojo: const impide reasignar la variable, pero el contenido de un objeto o array declarado con const sí se puede modificar.

    == vs. === y valores "falsy"

    == convierte los tipos antes de comparar ("5" == 5 da true). === compara valor y tipo ("5" === 5 da false). Usa siempre === y !==.

    En un if, los valores falsy principales son false, 0, "", null, undefined y NaN. Todo lo demás cuenta como verdadero.

    const nombre = null ?? "Anónimo";        // ?? solo actúa con null/undefined
const calle  = usuario?.direccion?.calle; // ?. evita el error si algo no existe
const copia  = [...nums, 4, 5];           // spread: copia y amplía un array

    Arrow functions y this

    Las arrow functions no tienen su propio this: heredan el del contexto que las rodea. Por eso no deben usarse como métodos de un objeto.

    const obj = {
  nombre: "Ana",
  mal: () => console.log(this.nombre),  // undefined
  bien() { console.log(this.nombre); }   // "Ana"
};

    Métodos de array que no modifican el original

    const nombres = productos.map(p => p.nombre);          // transforma cada elemento
const enStock = productos.filter(p => p.stock > 0);    // filtra
const total   = productos.reduce((acc, p) => acc + p.precio, 0); // acumula

    Delegación de eventos

    Los eventos "suben" desde el elemento pulsado hasta sus padres (bubbling). Por eso, en lugar de poner un listener en cada <li>, basta con uno en la lista padre:

    lista.addEventListener("click", (e) => {
  if (e.target.tagName === "LI") e.target.classList.toggle("seleccionado");
});

    Closures

    Una función interna "recuerda" las variables de la función que la creó, aunque esa función ya haya terminado. Es la forma clásica de tener variables privadas:

    function crearContador() {
  let cuenta = 0;                       // no accesible desde fuera
  return { incrementar: () => ++cuenta };
}

    Asincronía y Event Loop

    La asincronía ha evolucionado de los callbacks a las Promesas y de ahí a async/await, que permite escribir código asíncrono como si fuera secuencial, con los errores en un try/catch.

    JavaScript tiene un solo hilo. El Event Loop vacía siempre primero las microtareas (promesas) y después atiende las macrotareas (setTimeout, eventos):

    console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// Salida: 1, 4, 3, 2

    HTML semántico y accesibilidad

    Usar el elemento adecuado para cada cosa (<header>, <nav>, <main>, <article>, <aside>, <footer>) en lugar de <div> para todo da información extra a los lectores de pantalla y a otras herramientas, que así pueden orientar a la persona sobre lo que está navegando. MDN destaca que elegir bien los elementos es una de las bases de la accesibilidad, y uno de los sitios donde más se rompe cuando se hace mal.

    Flexbox y Grid

    Son los dos sistemas de maquetación modernos de CSS y se diferencian por las dimensiones que gestionan. Flexbox es unidimensional: distribuye el espacio entre elementos en una sola dirección a la vez, en fila o en columna (eje principal y eje transversal), y se le da bien alinear. Grid es bidimensional: define filas y columnas a la vez con grid-template-columns y grid-template-rows, y ofrece la unidad fr para repartir el espacio disponible. Se pueden combinar: una rejilla para la estructura de la página y flexbox dentro de cada componente.

    JSON y XML

    Ambos representan datos como texto, pero con enfoques distintos. El RFC 8259 describe JSON como un formato de intercambio de datos ligero, basado en texto e independiente del lenguaje, con cuatro tipos primitivos (cadenas, números, booleanos y null) y dos estructurados (objetos y arrays). XML, según el W3C, es un subconjunto de SGML cuyos documentos deben estar bien formados y, opcionalmente, ser válidos respecto a una definición de tipos; entre sus objetivos de diseño están ser legible para las personas y servir a una gran variedad de aplicaciones.

    Puntos clave

    • XML permite crear etiquetas propias; HTML tiene un conjunto de etiquetas fijo pensado para la web.
    • CSS separa el contenido (HTML) de su presentación visual mediante selectores y propiedades.
    • El DOM es la representación en memoria de la página que JavaScript puede leer y modificar.
    • Un ERP integra los procesos de una empresa; un CRM se centra en la relación con los clientes.
    • Un documento XML "bien formado" tiene una única raíz y etiquetas correctamente anidadas.

    Ponte a prueba

    ¿Qué diferencia hay entre XML y HTML?

    XML no tiene etiquetas fijas (se crean según lo que se necesite describir); HTML tiene un conjunto de etiquetas predefinido específico para páginas web.

    ¿Qué es el DOM?

    La representación en memoria de una página web como un árbol de objetos, que JavaScript puede leer y modificar sin recargar la página.

    ¿Qué diferencia hay entre un ERP y un CRM?

    El ERP integra los procesos internos de la empresa (inventario, contabilidad...); el CRM se centra en la relación con los clientes.

    ¿Qué hace que un documento XML esté 'bien formado'?

    Tener una única raíz y etiquetas que se cierran correctamente y están bien anidadas.
